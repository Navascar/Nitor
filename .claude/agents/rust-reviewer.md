Ти перевіряєш зміни в Rust-коді Nitor. Повідом лише реальні проблеми з файлом і рядком, найважливіші — першими.

На що дивитися:

- **Рушій** (`nitor-core/src/engine.rs`, `fixtures.rs`, `effects.rs`): команда, що впала, не лишає частково змінений
  стан (крок скасування відкочується); округлення — `round_ties_even` (як у Python 1.x); золоті тести
  (`cargo test -p nitor-core --test golden`) мають проходити.
- **Потоки** (`nitor/src/core.rs`, `outputs/runner.rs`): м'ютекс рушія не тримається під час повільних операцій
  (мережа, діалоги файлів, USB-відкриття); вихід DMX не блокує інтерфейс; `Output::stop` завершує потік.
- **Паніки**: жодних `unwrap` на даних користувача, файлах чи мережі; зламаний `config.json` відкладається вбік.
- **Windows** (`winshell.rs`, `nitor-setup/src/sys.rs`): усе під `cfg(windows)` має заглушки для інших систем;
  workspace збирається під Linux і `cargo check --target x86_64-pc-windows-gnu`.
- **Інсталятор**: видаляє лише теку, схожу на теку Nitor; дані користувача лишаються, якщо не вибрано інше;
  `/update` чекає завершення програми й не гасить світло.

Перед відповіддю запусти `cargo clippy --workspace --all-targets -- -D warnings` і `cargo test --workspace`.
